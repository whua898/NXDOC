Optimizing Within Constraints

Constraints are those conditions that the NC program must follow when dealing with the order of operations. The image below shows the Geometry View after applying the Holemaking Subtypes for a countersink hole and threaded simple hole. The constraint is that the order of operations defined below each feature group does not have to be violated during optimization. The spot drilling operations must come first, followed by drill, c-bore and deburring.

The image below displays the result after switching to the Program View. The operations are in a consecutive order exactly as they have been created. Some operations use the same tool (SPOT_DRILL_SIMPLE_HOLE_1, SPOT_DRILL_CB_HOLE_1 or DEBUR_SIMPLE_HOLE_1 and DEBUR_CB_HOLE) When passing this to the postprocessor there is a tool change at each operation. Operations that share the same tool can be rearranged to avoid unnecessary tool changes. In the optimization dialog the option to perform this is called Minimize Tool Change.

When you select Minimize Tool Change the system goes through the Program View and calculates the best order of operations. The best order of operations is the order that contains the least amount of tool changes without violating constraints. Therefore, the system has to consider the order of operations in the feature group. The picture below shows how the spot drilling operations have been reordered according to their tools. DEBUR_SIMPLE_HOLE_1 and DEBUR_CB_HOLE share the same tool and are arranged together accordingly. However, they need to be moved after the counterbore operations to follow the constraints as prescribed in the feature group.

The image below displays the results of optimization with the option Create Optimization Group selected. When this option is selected the system creates OPTIMIZED_NC groups for those operations that share the same tool. These tool paths can be combined for further optimization by using Minimizing Tool Travel and Banding.

Note:

Instanced or transformed operations are excluded from optimization.

Currently it is not possible to create NC_OPTIMIZED groups that contain operations belonging to different MCS. Optimize them individually by creating and arranging program folders for each MCS.
